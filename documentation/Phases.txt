Deliverable: Actual AI-powered interview preparation.

Current implementation: The AI service generates the opening question, evaluates each submitted answer, and adapts with a follow-up or a new competency question. It returns per-answer scores and a final report. Resume evidence is retrieved through the authenticated Node backend. Job-fit reports are generated from the selected resume evidence and uploaded job description on each run; required criteria carry four times the weight of preferred criteria in the deterministic fit score.

Voice is currently turn-based (browser speech recognition/playback plus an AI request after each submitted answer), not a continuous streaming or full-duplex audio connection.


Phase 8 — Credit-Based System
- Credit balance.
- Credit deduction.
- Credit transaction history.
- Usage tracking.
- Atomic database operations.
- Preventing duplicate deductions.
Deliverable: Working credit-based monetization system.

Current implementation: Wallet balances are backed by expiring credit lots and a transaction ledger. Resume analysis/re-analysis, job fit, and 5/10/20-question interviews reserve credits and settle only after successful work; unused interview reservations are released. Welcome credits expire after 90 days and purchased credits after 12 months. Packages are 500 credits/₹249, 1,200/₹499, and 3,500/₹999. A wallet page shows balance, usage, expiry, transactions, and package costs.


Phase 9 — Razorpay Integration
- Payment order creation.
- Checkout integration.
- Payment signature verification.
- Webhooks.
- Transaction records.
- Credit addition after verified payment.
Deliverable: Actual payment-to-credit workflow using Razorpay test mode.

Current implementation: The client launches Razorpay Checkout when credentials are configured. The backend creates INR orders, verifies the checkout signature and captured payment with Razorpay, validates signed webhooks, and grants credits idempotently. The local configuration is in test mode and has no Razorpay keys/webhook secret configured, so checkout is disabled. Live settlements require a Razorpay merchant account with KYC and a verified bank account; the provider settles funds per the merchant's settlement settings, not directly through this application.

Phase 11 — Advanced Engineering
- API rate limiting.
- Input validation.
- Secure file handling.
- Logging.
- API testing using Postman.
- Database indexing.
- Error handling.
- Security testing.
Deliverable: A more robust, production-oriented application.

Current implementation: API-wide rate limiting, Helmet, NoSQL sanitization, request logging, schema validation, private PDF storage, ownership checks, and Mongo indexes are present. Qdrant keyword indexes on `user_id` and `resume_id` are provisioned before filtered resume searches. Cross-origin idempotency headers are allowed. A Postman smoke-test collection is provided at `postman/api-post-c-pm-prabhavai.json`; it requires a Firebase ID token and covers read-only user/admin APIs plus the non-charging Razorpay order-configuration response. Database-backed billing integration tests and a formal security test pass are still required before production sign-off.
